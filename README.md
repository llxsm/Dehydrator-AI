# Dehydrator AI · 文字脱水机

把长文本榨成一句真话和一个动作。

**零依赖、零配置、零 API 也能跑。** 没有 `package.json`，不需要 `npm install`，只要 Node 18+。

---

## 它解决什么问题

有些文本你必须读，但没人替你读：学生手册、劳动合同、平台协议、隐私政策。
它们动辄十几万字，真正影响你的可能只有二十句，而且散落在第三十七条、附件四、第 8.2 款。

这个工具做的事很窄：**把这二十句捞出来，按后果轻重排好，翻译成一句人话，并告诉你它没写什么。**

- 学生读学生手册（缺课三分之一会怎样、申诉期几天）
- 个人开发者读合同和平台规则（哪些条款把责任推给你）
- 任何人读用户协议（你付出了什么）

## 快速开始

```bash
node scripts/selftest.mjs
```

一条命令，九项自检：环境、词库、**单元测试**、构建、**页面（把产物放进假 DOM 真跑一遍）**、Gold 评测、端到端、模型传输、模型配置。
**不需要 key，不需要联网。** 全绿就说明这个仓库是活的。

只想跑单元测试：

```bash
node --test tests/engine.test.mjs
```

## 三种用法

### 1. 离线版（不需要任何东西）

```
双击 dist/dehydrator-offline.html
```

单文件，不联网、不需要服务器、不需要 API key，断网也能用。
把任意 `.txt` 拖进去，或者点预设按钮（内置学生手册 2025 版，19.9 万字）。
页面会告诉你：这段文字里哪几句你**真该看**、原文里**哪几个字**是坑、以及它**没写**什么。

重新生成这个文件：

```bash
node scripts/build-offline.mjs
```

### 2. 命令行

```bash
node scripts/scan.mjs corpus/raw/学生手册2025.txt
node scripts/scan.mjs corpus/raw/学生手册2025.txt --top=8 --show=10
```

### 3. 本地服务（能接模型）

```bash
node scripts/serve.mjs
# 打开 http://localhost:3000
```

页面被这个服务托管时会自动走 `/api/dehydrate`，调用模型做排序和措辞；
双击打开或断网时，走同一套纯函数离线排序。**两条路径共用 `lib/rank.mjs`**，
所以页面上的清单和终端里的清单一定一致。

启用模型（可选）：把 `DEEPSEEK_API_KEY` 设进环境变量或 `.env.local`，
或者用任何 OpenAI 兼容端点（见 `.env.example`）。
**不配也完整可用**——模型失败会自动降级为确定性排序，报告照样出全。

## 它做什么，不做什么

| 做 | 不做 |
|---|---|
| 找出「会影响到你」的句子，按后果排序 | 不替你判断该不该签 |
| 从原文摘出「条件 + 后果」当标题 | 不编造原文里没有的内容 |
| 指出协议里缺了什么（管辖、解除、赔偿） | 不做法律意见，不保证覆盖所有风险 |
| 描述文本特征（谁有权、后果落在谁头上） | 不对任何主体作动机指控 |

## 工作方式（四段，只有第三段花 API 钱）

```
长文本
  ↓ L1 确定性：切句 + 词库 + 共现规则 → 候选句        ← 零成本、零延迟
  ↓ L1.5 确定性：代价门槛 → 有后果的句子               ← 30 条
  ↓ L2 模型：只读这 30 条，写标题和一句人话            ← 可选，无 key 自动降级
  ↓ L3 确定性：按后果去重 + 多样性排序 + 缺口检测      ← 与离线版同一条路径
```

实测（学生手册 2025 版）：**198,931 字 → 8,548 句 → 3,800 个实质句 → 131 条候选 → 30 处有后果 → 10 条清单**，全流程 130 ms（不含模型）。

词库是 91 条词条 + 12 条同句共现规则。Gold 集 29 条人工标注的现状：
标为「坑」的 17 条里，命中 11 条、边界 4 条、**硬误报 0**；未标记的 12 条里没有误抓。

## 词库怎么改

- 新增词条：在 `lexicon/entries/` 里找到对应类别的文件（一个类别一个文件），在 `entries` 末尾加一条，
  必须带 `why` 和 `advice`，建议带 `evidence`（真实语料里的原句）
- 新增规则：往 `lexicon/rules.zh-cn.v1.json` 的 `rules` 里加，`groups` 是两组词，
  同句内间隔不超过 `gap` 就算命中
- 改完跑 `node scripts/build-lexicon.mjs` 合并产物，再跑 `node scripts/check-all.mjs`

**不要手改 `lexicon/zh-cn.v1.json`**——它是产物，会被下一次构建覆盖。
合并只按源文件来，`check-all` 会比对两者是否一致。字段说明和校验规则见 `lexicon/README.md`。

纪律：**词条要精度，规则要召回。** 前者直接给用户看，后者只用来把句子喂给模型。

## 提交前

```bash
node scripts/check-all.mjs
```

五项：词库源结构与产物是否同步、密钥泄露、构建能否成功、`dist` 与 `docs` 是否一致、
页面脚本能不能真的跑起来。全绿再提交。`git commit` 时 `pre-commit` 钩子会自动跑其中较快的两项。

## 已知限制

这些是当前版本真实存在的短板，不是「以后再说」的客套话：

1. **隐私与数据域几乎失明。** 哔哩哔哩隐私协议 964 句只命中 9 条，
   「保留您的个人信息」「自动化决策」这类表述抓不到——词库主要覆盖接单、招聘、合同三个语域。
2. **长文的语域判定会偏向「合同」。** 学生手册 2025 版被判成 `contract`，
   于是缺口检测拿协议清单去查，结论是「该写的都写了」。语域判定按命中字段数量投票，长文里所有字段都能命中。
3. **规则层没有极性排除。** 「未经您同意，我们**不会**收集…」这种保护性表述会被当成风险，
   因为同句共现只看词，不看否定。
4. **模型只做排序和措辞，不做判断。** 它不会告诉你这条条款是否违法；没有 key 时连措辞都没有。
5. **没有 CI。** 检查靠本地 `check-all`，推上去之后没人替你跑。
6. **走模型时，候选句会发到你配置的端点。** 离线版不联网；本地服务接模型时，
   发出去的是那 30 条候选句（不含全文）。介意的话用离线版。

## 密钥

1. **key 只放 `.env.local`**，这个文件已被 `.gitignore` 覆盖，永远不会提交。
